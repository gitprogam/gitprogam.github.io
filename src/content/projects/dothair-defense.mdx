## 이게 뭐냐면

길 따라 몰려오는 족집게로부터 점털을 지키는 2D 타워디펜스예요. 문서 도구, 학습 앱 같은 다른 동아리 서비스랑은 결이 좀 다른, 일종의 사이드 퀘스트 같은 게임 프로젝트예요 ㅋㅋ 길목에 타워를 세워서 웨이브마다 몰려오는 족집게가 끝까지 못 가게 막으면 돼요. 지금 공개된 버전에는 타워가 세 종류(Yellow Mesh, Curly, Frost Hair) 있고, 웨이브는 두 개예요.

## 엔진만 세 개 써 봄

어떤 엔진으로 끝까지 갈지 처음부터 못 정해서, 세 개로 직접 만들어 보면서 비교했어요.

- **Godot:** 제일 처음 만든 프로토타입이에요. 에셋을 안 만들고 하다 보니 느낌이 살짝 구렸어요 ㅠㅠ 이건 [BBlog 개편 글](https://blog.binaryhub.club/bblog-gaepyeon/)에서 처음 소개했어요.
- **Unity 6:** 작은 범위를 처음부터 끝까지 완성해 보는 "수직 슬라이스"가 목표였어요. 경로 따라 움직이는 적, 웨이브 다섯 개, 목숨이랑 골드, 승패 판정, 타워 두 종류(한 놈만 노리는 거랑 주변을 한꺼번에 때리는 거), 격자에 타워 놓기, 화면 정보 표시까지 하나씩 만들고 브라우저에서 돌아가는 WebGL 로 빌드했어요.
- **Phaser(TypeScript):** 같은 게임을 웹 기술로도 다시 만들어 봤어요. 플레이되는 핵심 부분에 체력바, 2배속, 타워 쏠 때 반동 같은 손맛을 넣고, 휴대폰을 세로로 들면 가로로 돌려 달라는 안내 화면도 넣었어요.

지금 [공개된 버전](https://dothair.pages.dev)은 Unity 로 빌드해서 Cloudflare Pages 에 올린 거예요.

## 타워 업그레이드

타워디펜스는 결국 어떤 타워를 어떻게 키우느냐가 재밌는 거잖아요. 업그레이드는 경로 세 개(공격력, 유틸, 공격 속도)에 경로마다 두 단계로 짰어요.

대신 한 타워에서 다 올릴 수는 없어요. 한 경로를 2단계까지 올리면 다른 하나는 1단계까지만, 나머지는 아예 못 올려요. 그래야 같은 타워라도 어떻게 키웠냐에 따라 쓰임이 달라지거든요. 같은 "유틸"이라도 한 놈만 노리는 타워는 사거리가 늘고, 범위 공격 타워는 범위 피해가 늘게 타워마다 다르게 붙였어요.

업그레이드 규칙처럼 화면이랑 상관없는 계산은 엔진이랑 상관없는 코드로 따로 빼서 자동 테스트를 붙였어요. 엔진 안에서 하나하나 눌러 보면서 확인하면 규칙 바뀔 때마다 꼭 하나씩 놓치더라구요. 업그레이드 붙였을 때 기준으로 편집기에서 도는 테스트 18개가 이 규칙들을 지키고 있었어요. 타워는 기본 능력치랑 업그레이드 정보를 데이터로 들고 있다가, 업그레이드를 살 때마다 능력치를 다시 계산해요.

## 창이 가려지면 게임이 멈춤

이거 진짜 황당했는데요, Unity 편집기는 창이 화면에 실제로 보일 때만 게임 시간이 흘러가요. 최소화 안 했어도 다른 창 뒤로 완전히 가려지면 그냥 멈춰 있어요. 창이 보이는지 확인하는 기능도 "가려진 상태"는 못 알아채고, 백그라운드 실행 설정은 빌드된 게임에만 먹고 편집기엔 소용이 없었어요.

결국 게임 안의 프레임 수랑 시간 값을 직접 찍어 보고서야 알았어요. 둘 다 처음 값에서 꿈쩍도 안 하고 있더라구요.... 그 뒤로는 동작 확인할 때 Unity 창을 다른 창에 안 가려지게 띄워 두는 걸 규칙으로 정했어요.

## 포트 하나를 두 프로그램이 원함

AI 코딩 도구가 Unity 편집기의 장면이랑 오브젝트를 직접 만질 수 있게, 둘을 잇는 MCP 서버를 붙였어요. 근데 서버가 아예 안 뜨는 거예요. 더 헷갈렸던 건 그 주소로 요청을 보내면 응답이 멀쩡하게(200) 온다는 거였어요.

알고 보니 MCP 서버 기본 포트인 8080 을 같은 PC 의 프록시(Caddy)가 이미 쓰고 있었어요. 응답한 건 MCP 서버가 아니라 프록시였던 거죠 ㅋㅋ 그 포트를 누가 듣고 있는지 직접 확인하고 나서야 알았고, MCP 서버를 8090 으로 옮겨서 해결했어요. 응답이 온다고 내가 띄운 게 응답하는 건 아니더라구요.
